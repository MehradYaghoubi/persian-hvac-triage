# مدل کوچک فارسی برای دسته‌بندی درخواست خدمات گرمایش

[English documentation](README.md) · [گزارش آزمایش](docs/synthetic-results.json) · [محیط ثبت‌شده](docs/experiment-environment.json)

یک CNN کاراکتری با ۵٬۷۴۴ پارامتر که از صفر آموزش می‌بیند و متن فارسی مشتری را بر اساس نشانهٔ گزارش‌شده یا نوع درخواست دسته‌بندی می‌کند. مثلاً «رادیاتور سرده» به گروه گرمایش می‌رود. مدل علت خرابی، قطعهٔ معیوب یا خطر اضطراری را تشخیص نمی‌دهد.

## خروجی واقعی API

![اجرای واقعی مدل آموزش‌دیده در Swagger](docs/images/prediction-api.png)

این تصویر از API محلی و وزن‌های آموزش‌دیده گرفته شده است؛ ورودی آن ساختگی است. [منشأ تصویر](docs/images/provenance.json) ثبت شده است.

## نتیجهٔ آزمایش محدود

![نمودار دادهٔ ساختگی؛ مقایسه مدل با baseline](docs/images/synthetic-results.png)

| مورد | مقدار ثبت‌شده |
|---|---:|
| نمونهٔ آموزش / اعتبارسنجی / آزمون | ۱۲۰ / ۸ / ۱۶ |
| تعداد پارامترها | ۵٬۷۴۴ |
| حجم فایل وزن | ۲۵٬۴۷۵ بایت |
| Macro-F1 مدل CNN | ۰٫۹۳۳ |
| Macro-F1 روش تطبیق واژه | ۰٫۴۰۴ |
| آستانهٔ ارجاع | ۰٫۴ |
| میانگین تاریخی اجرای CPU | حدود ۰٫۳۵۷ میلی‌ثانیه |

داده‌ها کاملاً تألیفی و ساختگی‌اند. فقط ۱۶ مثال آزمون و یک seed داریم؛ امتیاز بالا اثبات کیفیت روی مشتری واقعی نیست. baseline فعلی تطبیق واژه است؛ TF-IDF یا مدل پیش‌آموزش‌دیده نیست. زمان فقط اجرای درون پردازش در یک اندازه‌گیری محلی است؛ شبکه، شروع برنامه و بار هم‌زمان را شامل نمی‌شود. حجم PyTorch از فایل وزن بسیار بزرگ‌تر است.

گزارش کامل یک خطا هم دارد: پیام مربوط به نمایش خطا، «درخواست نصب» تشخیص داده شده است. این خطا حذف نشده و همراه با نتایج منتشر می‌شود.

## دسته‌ها و روش

هشت برچسب عبارت‌اند از مشکل آب گرم، مشکل گرمایش، نشتی آب، کد خطا، صدای غیرعادی، سرویس، نصب و قیمت. اگر امتیاز زیر آستانه باشد، `review` برمی‌گردد. امتیاز softmax احتمال کالیبره‌شده نیست؛ مدل ممکن است با اطمینان بالا اشتباه کند.

معماری: نرمال‌سازی فارسی ← ۱۶۰ شناسهٔ کاراکتر ← embedding با ۲۴ بُعد ← Conv1d با ۴۸ کانال و kernel سه ← ReLU و max pooling ← هشت خروجی.

داده‌ها در `data.py` هستند. خانواده‌های عبارت **پیش از افزودن سلام و پیشوند** بین آموزش، اعتبارسنجی و آزمون جدا می‌شوند. آستانه فقط از validation انتخاب می‌شود و challenge وارد آموزش نمی‌شود. این روش جلوی نشت عین قالب‌ها را می‌گیرد، اما سوگیری واژگانی یا کمبود تنوع را برطرف نمی‌کند.

## اجرای قابل‌بازتولید

Python 3.11 یا بالاتر و نسخهٔ سازگار PyTorch لازم است:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python train.py
python -m unittest -v
python -m uvicorn serve:create_app --factory --host 127.0.0.1 --port 8001 --no-access-log
```

آموزش روی CPU اجرا می‌شود و کلید API نمی‌خواهد. وزن و metadata و report در `artifacts/` ساخته می‌شوند؛ این خروجی‌ها وارد Git نمی‌شوند و با `train.py` دوباره تولید می‌شوند. گزارش داخل `docs/` مربوط به آزمایش اولیه است و زمان اجرای دوباره ممکن است فرق کند.

در `http://127.0.0.1:8001/docs` درخواست `POST /predict` با بدنهٔ `{"text":"رادیاتور سرده"}` را اجرا کنید. خروجی شامل `label`، `score` و `advisory_only: true` است. ورودی حداکثر ۲٬۰۰۰ نویسه می‌گیرد ولی مدل از ۱۶۰ نویسهٔ نرمال‌شدهٔ اول استفاده می‌کند. مسیر وزن را می‌توان با `MODEL_DIR` تنظیم کرد.

## اتصال و محدودیت استقرار

دستیار مخزن دیگر با `TRIAGE_URL=http://127.0.0.1:8001` به این مدل متصل می‌شود. تصمیم ایمنی به این مدل وابسته نیست. API احراز هویت عمومی ندارد و باید روی loopback یا شبکه خصوصی بماند. فقط وزن‌های مورداعتماد خودتان را بارگذاری کنید.

Dockerfile موجود است، اما اجرای Docker روی هاست کاربر بررسی نشده است. هاست اشتراکی cPanel ممکن است فضای کافی برای PyTorch نداشته باشد؛ اجرای مدل برای دستیار سایت اختیاری است.

برای قوی‌ترشدن نمونه‌کار باید دادهٔ مستقل بیشتر، baseline خطی TF-IDF، ورودی خارج از دامنه، چند seed و کالیبراسیون بررسی شوند. این موارد فعلاً قابلیت پیاده‌شده محسوب نمی‌شوند.
